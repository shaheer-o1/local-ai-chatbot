# sparrow AI
#### Video Demo: https://youtu.be/YLs3SU_yLqY
#### Description:
This project is a fully offline AI chatbot that uses .gguf models through the llama.cpp inference engine. Being offline it provides an LLM using only local hardware and does not require cloud APIs such as those from openAI or anthropic, it has full privacy as the data never leaves the users device and there are zero API costs as it is locally hosted on port 5000.

To run the project you need to download the files to your local folder/directory, setup llama.cpp seperately and download an open soure .gguf format model from websites like huggingface. The model should go into the models folder (create it first) and llama.cpp should be extracted to the llama folder (create it first). Open config.py and copy the last comment and paste into the terminal, modify the comment according to your file paths and model name. Press enter and the model should load and start listening, then open another terminal with the first one running in the background and type "flask run --debug" and press enter now go to your browser and go to the link flask is running on which can be seen from the terminal in which the command was typed.

The first file I setup was the config.py file where I set basic things such as the system prompt that goes into the LLM everytime a message is sent because LLMs are stateless and require complete history for each message. It also contains the Llama.cpp url which the app connects to for getting answers from the model. I also set the max context size according to the load my device could handle which can also be seen from the demo where the responses are taking long due to my hardware being restricted to 6gb ram and an HDD, that said this can be optimized further using a lower parameter model but I chose to use the one I did for max smarts.

The second file was app.py where I setup the app and created three paths which get and send data to the client side through javascript fetch(), this was a design choice I made because I did not want to render_template or redirect the user to another page instead I wanted the user to see history being updated in real time in the same page, which is why I used fetch(). The clear route is for clearing the chat session history and setting it back to an empty list to start a fresh conversation.

Then came index.html which contains the html and the css for the webpage which renders chat bubbles as seperate divs and uses jinja2 to dynamically append user history that is sent by app.py. For the styling I mainly used bootstrap classes and added my own styles on top in the same file, another choice I made instead of using styles.css. I used custom made Keyframe animations for smooth bubble movement and user friendly design. On top of that I had to use translate(y) to make the transition from the empty state to the non empty state where there is no user history yet, smooth.

Then I wrote script.js where I dynamically added the user message and the bot's answer to the page using async functions so that the page does not freeze while the answer is being generated. It also contains code that times out the bubbles before clearing the chat to make it look smoother as the bubbles fade away. Using js I dynamically switched the state from empty to non empty when a message was sent using the sendmsg() function and then back to the empty state using the clearchat(), this allowed for dynamic designs and smooth animations that are based on the class of empty and non empty states.

helpers.py was taken from CS50's own finance pset from which I wanted to use the login_decorator but I scratched that idea, right now helpers.py has no function in the project.

test_model.py was a file I initially created to just run the model in the terminal to confirm that it works before building the web app.

model.py is the file that actually talks to llama.cpp and sends to and gets the answer back from the model before passing it to app.py, it uses standard key values pairs for history making because that is the way llama.cpp is designed to work according to their documentation, they only choice I made in this was limited variable naming and the actual logical structure which is my own.
